# Платформы: Claude Code и DSH

Набор RevRef — это Markdown-инструкции, скрипты и git-протоколы, поэтому он работает в любом агенте, который читает файлы, запускает команды и умеет работать с git. Главных платформ две: **Claude Code** и **DSH** (DeepSeek Harness). Правила, протоколы и файлы `.revref/` у них общие; различаются инструменты, субагенты, сторожевая проверка и лимит токенов. Этот файл читается вместе с `SKILL.md` и не отменяет `ORCHESTRATOR.md`, `PIPELINE.md`, `POLICY.md` и `PROTOCOLS.md`.

## Определение платформы

- **Claude Code:** есть инструменты `Task` (именованные агенты), `Bash`, `Read`, `Write`, `Edit`, `TodoWrite`; хуки из frontmatter `SKILL.md` выполняются.
- **DSH:** есть инструменты `subagent` (или `subagent_fork`), `pwsh` на Windows или `bash` на macOS и Linux, `read`/`write`/`edit`, `todo_write`; команда `/revref` подхватывается из `~/.dsh/skills/revref` или `<проект>/.dsh/skills/revref`; хуки не выполняются.

Если платформа неочевидна, посмотри список инструментов в системной подсказке. Всё, что не описано ниже, одинаково.

## Соответствие инструментов

| Задача | Claude Code | DSH |
|---|---|---|
| Команда оболочки | `Bash` (на Windows — `PowerShell`) | `pwsh` (Windows) или `bash` (macOS, Linux) |
| Чтение файла | `Read` | `read` |
| Запись и правка | `Write`, `Edit` | `write`, `edit` |
| Поиск файлов и строк | `Glob`, `Grep` | `glob`, `grep` |
| Список задач | `TodoWrite` | `todo_write` |
| Субагент | `Task` (именованный агент или general-purpose) | `subagent` (свежий ребёнок), `subagent_fork` (с префиксом истории родителя) |
| Вопрос владельцу | `AskUserQuestion` | `ask_user_question` |
| Веб | `WebFetch`, `WebSearch` | `web_fetch`, `web_search` |

## Субагенты

### Claude Code

Роль передаётся именованному агенту (`revref-reviewer`, `revref-verifier`, `revref-fixer`) или агенту общего назначения; вызов `Task` синхронный и возвращает результат. Исполнитель запускается с `isolation: "worktree"`.

### DSH

- **Вызов асинхронный.** `subagent` сразу возвращает `started subagent <id>`, а итоговый текст ребёнка приходит позже отдельным сообщением в историю родителя. Не жди результата синхронно, не опрашивай и не спи: запусти партию независимых детей одним сообщением, продолжай полезную работу (запись состояния, чекпоинт) и заканчивай ход, если ждать больше нечего, — уведомление разбудит простаивающего родителя.
- **Ребёнок не видит твой контекст.** В `prompt` передавай всё нужное: описание роли, пакет задачи по `PROTOCOLS.md` §1, абсолютные пути к промптам, область и ограничения. Если инструментов `Task` нет, роль читается ребёнком из `roles/<роль>.md` по абсолютному пути.
- **Пределы.** По умолчанию до 8 живых детей на дерево, очередь не создаётся, глубина 1: ребёнок не может запускать своих детей. Держи `CONFIG.Параллельность` в этих пределах; следующую партию запускай после уведомлений предыдущей.
- **Сбор результатов.** На каждого ребёнка приходит одно уведомление с его финальным текстом. Ответ должен быть по формату `PROTOCOLS.md` §1, не длиннее 15 строк. Пустой финальный текст считается «нет ответа» — задачу нужно перезапустить или выполнить самому.
- **Доуправление.** Локального ребёнка можно дослать сообщением после завершения (`send_message`) или прервать текущий ход (`interrupt_agent`); `list_agents` даёт снимок состояний, но не ожидание.
- **Agent Teams.** Если включён экспериментальный профиль команд, инструменты `subagent`/`subagent_fork` заменяются на `spawn_teammate` и `team_task_*`, рабочая папка у всех общая. Тогда роль — это teammate, а задачи — записи доски; правило «один писатель» соблюдается по-прежнему. По умолчанию этот режим выключен, и набор рассчитывает на `subagent`.
- **Без субагентов.** Если механизма субагентов нет совсем, выполняй роли последовательно по `ORCHESTRATOR.md`, правило 8.

### Worktree для исполнителей в DSH

В DSH нет режима изоляции у субагента: worktree создаёт оркестратор и передаёт его путь в `cwd` ребёнка.

```bash
git worktree add ../revref-wt/<ID> -b revref/task/<ID> HEAD
# субагент-исполнитель работает с cwd = ../revref-wt/<ID>
git -C ../revref-wt/<ID> add -A && git -C ../revref-wt/<ID> commit -m "revref(W<n>): <задача> ..."
git merge --no-ff revref/task/<ID>
git worktree remove ../revref-wt/<ID>
```

## Оболочка

- **Claude Code** выполняет команды через `Bash` (на Windows — `PowerShell`), состояние между вызовами сохраняется в пределах сессии.
- **DSH** запускает `pwsh -Command <команда>` (Windows) или `bash -c` (macOS, Linux) каждый раз в новом процессе: состояние не сохраняется, `cd` не переносится. Передавай рабочий каталог параметром инструмента и используй абсолютные пути либо `git -C <путь>`. Синтаксис одной платформы в другой не переводится.
- **POSIX-скрипты набора** (`hooks/guard.sh`, `bin/update.sh`, `hooks/usage.sh`) требуют `sh`. На Windows DSH документированного запуска POSIX-скриптов нет: если установлен Git for Windows, можно вызвать `& 'C:\Program Files\Git\bin\sh.exe' <скрипт> …`, но это неподдерживаемый приём; без него выполняй те же шаги вручную (`PROTOCOLS.md` §11 → «Без `sh`»).
- **Песочница.** В режиме только чтения PowerShell переходит в ConstrainedLanguage, а в обоих ограниченных режимах захват вывода чужой программы через pipe может завершиться `EPERM`. Для прогона нужен режим, разрешающий запись и запуск команд.

## Сторожевой хук

- **Claude Code:** хук `hooks/guard.sh` подключается автоматически через frontmatter `SKILL.md` и файлов агентов и блокирует опасные git-команды и коммит секретов, пока в репозитории есть `.revref/STATE.md`. Ничего дополнительно делать не нужно.
- **DSH:** хуков инструментов нет — ни `PreToolUse`, ни файла настроек хуков. Автоматически перехватить команду навык не может; детерминированный перехват возможен только отдельным плагином DSH. Поэтому в DSH проверка **обязательная и ручная**: перед каждой командой, которую защищает `POLICY.md` → «Git» (смена ветки, коммит, merge, push, reset, rebase и т.п.), сначала запусти проверку той же команды:

```powershell
# Windows / DSH
pwsh "<каталог скилла>/hooks/guard.ps1" -Command "git push --force"
# macOS, Linux или Windows с Git Bash
sh "<каталог скилла>/hooks/guard.sh" --check "git push --force"
```

- Код 0 — команду можно выполнять; код 2 — запрещено, причина в stderr, команду не запускай и не обходи другим способом; код 3 — проверка недоступна (нет POSIX-оболочки): сверься с правилами `POLICY.md` вручную и сообщи владельцу, что хук не работает.
- Проверяй и `git commit`: сторожевой хук дополнительно ловит секреты в сообщении коммита и в добавляемых строках `.revref/` и `docs/revref/`.
- Блокировка достижима и в Claude Code, и в DSH одинаково; различается только способ запуска.

## Лимит токенов

- **Claude Code** передаёт проценты лимитов подписки только команде статусной строки; `hooks/usage.sh` сохраняет их, оркестратор читает через `--read` (`PIPELINE.md` → «Лимит токенов»).
- **DSH** не имеет ни статусной строки, ни доступа агента к данным о лимите подписки. `hooks/usage.sh` здесь не работает. Если в `CONFIG.md` задан порог лимита, при `init` и в `status` пиши «не отслеживается», один раз сообщи владельцу и дальше опирайся на бюджет времени (`CONFIG.Бюджет времени`). Процент не оценивай по своим подсчётам токенов: это недостоверно. Владелец может отслеживать лимит сам и остановить прогон командой.

## Сессии, контекст и чекпоинты

- Файлы `.revref/` и протокол чекпоинта одинаковы. При сжатии контекста в DSH (оно происходит автоматически) и при любом сомнении перечитывай `STATE.md` и `PLAN.md`, как требует `ORCHESTRATOR.md`.
- Сжатие контекста не отменяет чекпоинты: перед долгим ожиданием субагентов и в конце шага состояние должно быть в файлах.
- `/revref resume` в новой сессии — штатный путь после обрыва. В DSH загруженный текст навыка обновляется при следующем вызове `/revref`, но уже вставленный в текущий ход текст устаревает; после `/revref update` начинай новую сессию.
- Автопродолжение по цели (goal) в DSH непостоянно и снимается при возобновлении сессии — не рассчитывай на него, работай командами.

## Автономный цикл DSH

Плагин `dsh-client-auto-continue` в режиме «Автономный цикл» (`resumeCompletedTurns`) после каждого завершённого хода сам отправляет «Продолжай». Лимита успешных продолжений нет: остановить цикл могут только владелец (переключатель сессии, пауза, Stop) или `turn/end:blocked`. Навык не может управлять плагином — ни пауза, ни смена режима из него недоступны.

Следствие: в автономном цикле нельзя заканчивать ход «пустым» — статусом, пересказом или повторной карточкой без новых действий. Плагин воспримет это как обычное завершение, пришлёт «Продолжай», и ход начнёт повторяться. Когда модель повторяется, включается **loop guard** плагина: он отменяет ход (`agent.cancel`) и перезапускает его после cooldown с текстом «Похоже, ты застрял в цикле. Перестань повторять последнее действие и продолжай другим способом». Полезной работы при этом не происходит.

Loop guard срабатывает по любому из сигналов (пороги настраиваются в плагине, значения по умолчанию):

- 4 подряд одинаковых сообщения ассистента (любой длины);
- 4 почти одинаковых абзаца внутри одного потокового сообщения;
- 12 коротких (меньше 40 символов) сообщений за 30 с без вызова инструмента между ними;
- 5 вызовов одного инструмента с теми же аргументами и тем же результатом.

Что делает RevRef:

1. **Ход заканчивается только двумя способами:** либо есть автономная работа — и ход завершается сделанным делом; либо работы без владельца не осталось — тогда `wait` (`PROTOCOLS.md` §13): полный чекпоинт «остановлен: ждёт ответов владельца» и блокирующий вопрос через `ask_user_question` (в Claude Code цикл ход не продолжает, поэтому блокирующий вопрос там не обязателен — достаточно карточек и конца хода).
2. **Блокирующий вопрос держит ход открытым.** Пока владелец не ответил, `turn/end` не наступает, поэтому автономный цикл не шлёт «Продолжай». Это и есть остановка прогона без вмешательства в плагин.
3. **Перед вопросом проверь, что работа действительно исчерпана** по чек-листу `PROTOCOLS.md` §13 → «Когда останавливаться». Пока есть хотя бы одна задача, проверка или слияние, не зависящие от ответов, — работай, не спрашивай.
4. **Loop guard — сигнал, а не способ работы.** Если пришёл текст «Похоже, ты застрял в цикле…», не повторяй то же действие: проверь чек-лист исчерпания; есть работа — смени подход, нет — переходи к `wait`.
5. **Не повторяй карточки и статусы.** Второй похожий статус подряд — уже риск срабатывания loop guard; вместо повтора — чекпоинт и `wait` (или конкретное новое действие).
6. **Любая остановка без дальнейшей работы** — бюджет времени (W9), порог лимита токенов, «готово к слиянию», завершённый или влитый прогон — в цикле тоже проходит через `wait`: карточки и блокирующий вопрос «ждать или выключить цикл / выполнить команду владельца». Иначе цикл продолжит ход вхолостую и упрётся в loop guard.

Понять, что сессия в автономном цикле, можно по повторяющимся сообщениям «Продолжай»/«Continue» без текста владельца; надёжнее — зафиксировать это при `init` в `CONFIG.md` («Автономный цикл (DSH): да»). Если цикл выключен, `wait` работает как обычная остановка: чекпоинт, карточки, конец хода.

**Ограничение.** Остановить сам автономный цикл навык не может: это делает только владелец (переключатель сессии, пауза, Stop). Если владелец не отвечает и хочет прекратить продолжения — он выключает цикл в переключателе сессии. Если прогон завершён или влит, а цикл остался включён, повторные «Продолжай» бессмысленны: скажи об этом одной строкой и предложи выключить цикл, не повторяя статус.

## Аргументы команды

- **Claude Code** подставляет `$ARGUMENTS` в `SKILL.md`.
- **DSH** не подставляет ничего: сообщение владельца остаётся дословным (`/revref review SEC`), а текст навыка вставляется следом. Аргументы читай из самого сообщения владельца: всё, что идёт после токена `/revref`. Так и написано в `SKILL.md`.
- Команды самого DSH (например `/permission`, `/compact`) получают свободный текст, но навыки — нет; не рассчитывай на разбор аргументов хостом.

## Установка и обновление в DSH

- Глобально: `${DSH_HOME:-~/.dsh}/skills/revref`; в проекте: `<корень проекта>/.dsh/skills/revref`. Проектная установка перекрывает глобальную: корень проекта DSH ищет по ближайшему `.git`.
- Установка: `./install.sh --dsh` или `./install.ps1 -Dsh`; с проектом — `--project <путь>` / `-Project <путь>`. Именованные файлы агентов не ставятся: роли лежат в `roles/` набора.
- В DSH команда появляется в меню `/` после нового сеанса или перезагрузки страницы: клиент кэширует каталог навыков на сессию. Навык помечен `disable-model-invocation`, поэтому в каталоге модели его нет — это нормально, запускает только владелец.
- Обновление: `/revref update` или `bin/update.sh` (на Windows — через `sh`, при наличии Git Bash). Обновление в проекте, закоммиченное в git, меняет пути `.dsh/skills/revref` (а не `.claude/skills/revref`); `PROTOCOLS.md` §11 учитывает платформу из `INSTALL`.

## Инструкции проекта

DSH читает `AGENTS.md`, `CLAUDE.md`, `AGENTS.local.md`, `CLAUDE.local.md` в `$DSH_HOME`, в `$DSH_AGENTS_HOME` и в каждом каталоге от корня проекта до рабочего каталога, с бюджетом 64 КБ; более конкретный файл важнее. Каталог `.dsh/` для инструкций не читается, `.claude/rules/` и импорты `@путь` игнорируются. Свои ревью проекта живут в `.revref/reviews/` и работают одинаково на обеих платформах.

## Чек-лист прогона в DSH

1. Убедись, что сторожевой хук доступен (`hooks/guard.ps1` или `hooks/guard.sh --check`), и проверяй им каждую защищённую git-команду.
2. Запускай субагентов партиями в одном сообщении, продолжай работу и собирай уведомления; не превышай 8 живых детей.
3. Исполнителям создавай worktree сам и передавай его в `cwd`.
4. `CONFIG.Лимит токенов` в DSH — «не отслеживается» или данные владельца; опирайся на бюджет времени.
5. Перед сменой платформы или обновлением набора — полный чекпоинт; после обновления — новая сессия и `/revref resume`.
6. Если автономная работа исчерпана и нужны ответы владельца — `wait` (`PROTOCOLS.md` §13), а не пустой статус: иначе автономный цикл продолжит ход и упрётся в loop guard.
