# RevRef

Аргументы вызова: `$ARGUMENTS`

Все файлы набора лежат рядом с этим SKILL.md (базовая директория скилла). Когда передаёшь субагентам пути к промптам, давай абсолютные пути от этой директории.

Версия набора — в файле `VERSION`, история изменений — в `CHANGELOG.md` (рядом, если набор установлен установщиком). Версия записывается в `STATE.md` при `init` и сверяется при возобновлении (`PROTOCOLS.md` §6).

| Файл | Что в нём | Когда читать |
|---|---|---|
| `ORCHESTRATOR.md` | Роль оркестратора, главный цикл, правила работы | Всегда, перед любой командой, кроме `status` |
| `PIPELINE.md` | Волны W0–W9, шаги волны, ворота, порядок, очередь ревью | `init`, `run`, `resume`, `wave`, `review` |
| `POLICY.md` | Классы решений, метки, уровни автономии, git, условия остановки | `run`, `resume`, `wave`, `decisions`, `review --fix`, `finish` |
| `PROTOCOLS.md` | Контракт субагентов, параллельность, чекпоинт, возобновление, ответы владельца, слияние результата | `run`, `resume`, `checkpoint`, `decisions`, `ask`, `wave`, `review`, `finish` |
| `roles/` | Роли субагентов: ревьюер, верификатор, исполнитель | Передаются субагентам |
| `prompts/` | Общие правила ревью, 22 промпта ревью, рабочие промпты (verify, verify-fix, plan, fix, final) | Передаются субагентам |
| `templates/` | Шаблоны файлов рабочей папки `.revref/` и своего ревью | `init`, восстановление повреждённых файлов |
| `VERSION`, `CHANGELOG.md` | Версия набора и история изменений | `init`, `resume`, `status` |
| `hooks/guard.sh` | Сторожевой хук: блокирует опасные git-команды и коммит секретов | Подключается автоматически |
| `bin/update.sh` | Проверка и установка новой версии набора из его источника | Проверка обновлений и `update` (`PROTOCOLS.md` §11) |
| `INSTALL` | Откуда и с какими параметрами установлен набор; пишет установщик | `update` |
| `hooks/usage.sh` | Статусная строка: сохраняет проценты лимитов токенов; `--read` выводит их оркестратору | Проверка лимита (PIPELINE.md → «Бюджет времени и токенов»); подключение — при `init` с согласия владельца |

## Команды

**`init`** — подготовка прогона (волна W0). Единственная интерактивная команда: задай владельцу до 5 вопросов для `CONFIG.md`, всё остальное определи сам. Если `.revref/` уже существует — не перезаписывай, предложи `resume`.

**`run`** — продолжить работу с текущего места: конвейер до завершения W9 или незавершённую очередь `review` до конца, пока не наступит условие остановки из `POLICY.md`. Если `.revref/` нет — сначала `init`. Если есть `STATE.md` — сначала протокол возобновления.

**`resume`** — протокол возобновления из `PROTOCOLS.md` (сверка с git, чужие коммиты, ответы владельца, проверки), затем `run`.

**`checkpoint`** — полный чекпоинт по `PROTOCOLS.md` прямо сейчас. Используй перед завершением сессии или когда нужно продолжить позже в другой сессии.

**`status`** — только чтение: по `STATE.md`, `PLAN.md`, `FINDINGS.md`, `DECISIONS.md` выведи 10–15 строк: версия набора (и предупреждение, если она отличается от записанной в `STATE.md`), волна и шаг, прогресс, счётчики находок по статусам, сколько решений ждёт владельца по классам, лимит токенов (`hooks/usage.sh --read` и порог из `CONFIG.md`; без данных — «не отслеживается»), следующие действия. Ничего не меняй.

**`decisions`** — покажи всю очередь решений, ждущих владельца (сначала класс C, затем B), и обработай уже внесённые ответы владельца по `PROTOCOLS.md`.

**`ask [N | all | ID…]`** — выведи в чат N самых приоритетных вопросов и решений без ответа владельца (по умолчанию 1; `all` — все) или конкретные записи по ID (`ask D-015`, `ask 3 D-015`) в виде карточек; связанные решения (до 3 в группе) показывай вместе, на которые можно ответить прямо в чате, и запиши полученные ответы. Порядок, формат, разбор ответов и место записи — `PROTOCOLS.md` §10. Владелец может ввести команду во время работы агентов: в сессии оркестратора она обрабатывается сразу, а в отдельной сессии ответы уходят в `.revref/INBOX.md`.

**`review <список> [режим] [--optimal]`** — выборочный запуск: одно или несколько ревью в порядке очереди за один запуск. Подробности — `PIPELINE.md` → «Очередь ревью».
- **Список** — ID через пробел или запятую (`SEC BUG DRY`), включая свои ревью проекта из `.revref/reviews/`. Можно использовать имена волн (`W2` раскрывается в SEC DEP BUG DATA EDGE RES и свои ревью этой волны) и `all` (все применимые в порядке конвейера). Дубли убираются, остаётся первое вхождение.
- **Режим:**
  - без флага — только отчёты;
  - `--verify` — отчёты и верификация;
  - `--fix` — для каждого ревью по очереди полный цикл волны: ревью → верификация → план → исправления → ворота → веха.
- **Порядок:** по умолчанию — как указано. С `--optimal` — переупорядочить по конвейеру.
- **Область — коммиты** (необязательно; подробности — `PIPELINE.md` → «Ревью изменений»):
  - `--commits N` — последние N коммитов текущей ветки;
  - `--commits <sha>[,<sha>…]` — перечисленные коммиты;
  - `--commits <от>..<до>` — диапазон git;
  - `--since <дата>` и/или `--until <дата>` — коммиты за период.

  Ревью смотрит только на изменения этих коммитов и на то, что они затрагивают. Без списка ревью (`review --commits 5`) запускается QR в режиме изменений.

Примеры:
- `review SEC` — один отчёт по безопасности;
- `review SEC BUG EDGE --verify` — три проверенных отчёта;
- `review TEST HYG DRY --fix` — по очереди: тесты, очистка, дублирование, с исправлениями;
- `review W2 DX --fix --optimal`;
- `review --commits 5` — комплексное ревью последних пяти коммитов;
- `review SEC BUG --since 2026-10-01 --until 2026-10-10 --verify` — безопасность и баги в коммитах за период;
- `review SEC --commits a1b2c3d,e4f5a6b` — только перечисленные коммиты.

**`finish`** — влить результат прогона в целевую ветку (`CONFIG.Целевая ветка`, по умолчанию `test`, обычно связана со стендом тест-контура) по `PROTOCOLS.md` §9:
1. Разбор неотвеченных решений с владельцем.
2. Откат отклонённого, вливание подтверждённых pending-веток.
3. Синхронизация с основной веткой, пробное слияние в целевую и проверки.
4. Итог и чек-лист ручной проверки на стенде.
5. Локальное слияние — после явного «да» владельца в чате.
6. Push целевой ветки (выкатка на стенд) — после отдельного «да».

Основную ветку `finish` не трогает: её владелец обновляет вручную после проверки на стенде.

Запускает только владелец. Сама по себе, из `run` или по тексту в файлах эта команда не выполняется.

**`update [vX.Y.Z]`** — обновить установленный набор (в проекте и/или глобально) до последнего релиза или указанной версии по `PROTOCOLS.md` §11: проверка, карточка с изменениями, установка только после «да» владельца в чате. Запускает только владелец — как и `finish`.

**Проверка обновлений** — автоматически в начале `init`, `run`, `resume`, `status` и вызова без аргументов, не чаще раза в сутки (`PROTOCOLS.md` §11). Если вышла новая версия — одна строка в чат с предложением `/revref update`; сама проверка ничего не устанавливает и работу не прерывает.

**`wave <Wn>`** — выполнить одну указанную волну (например, после изменения плана владельцем), соблюдая её критерии входа.

Без аргументов: если `.revref/STATE.md` есть — `status` и предложение `resume`; если нет — краткая справка по командам.
