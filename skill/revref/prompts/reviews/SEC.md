# SEC — Безопасность

Префикс ID находок: SEC. Применяй вместе с `prompts/common-rules.md`.

Проведи ревью безопасности с мышлением атакующего.

Начни с краткой модели угроз: что в системе ценно (данные, деньги, доступы), кто может атаковать (анонимный пользователь, авторизованный пользователь, участник той же сети, человек с доступом к репозиторию или серверу), какие есть точки входа.

Проверь:
- аутентификацию: хранение паролей, сессии и токены (срок жизни, отзыв, хранение на клиенте), восстановление доступа, защиту от перебора;
- авторизацию: проверку прав на каждом действии и объекте, IDOR, повышение привилегий, проверки только на клиенте;
- инъекции: SQL/NoSQL, command, code, шаблоны; path traversal; небезопасную десериализацию; SSRF;
- веб: XSS, CSRF, CORS, заголовки безопасности, open redirect, загрузку файлов;
- криптографию: устаревшие алгоритмы, захардкоженные ключи, собственные реализации, качество генерации случайных значений;
- секреты: в коде, конфигах, истории git, логах, сообщениях об ошибках, клиентском бандле;
- небезопасные настройки по умолчанию, режим отладки в продакшене, раскрытие внутренней информации;
- ограничение частоты запросов и защиту от исчерпания ресурсов;
- уязвимые зависимости (запусти audit-инструмент экосистемы; подробный разбор — в ревью зависимостей).

Учитывай специфику домена проекта: например, для сетевых сервисов — защиту протокола, ключей и конфигурации; для платежей — целостность и неповторяемость операций.

Для каждой уязвимости: сценарий эксплуатации по шагам, что нужно атакующему, последствия, меры устранения. Уязвимости без реального пути эксплуатации помечай как гипотезы.
