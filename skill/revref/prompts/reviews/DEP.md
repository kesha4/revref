# DEP — Зависимости и цепочка поставок

Префикс ID находок: DEP. Применяй вместе с `prompts/common-rules.md`.

Проведи ревью зависимостей проекта. Найди:
- пакеты с известными уязвимостями (используй audit-инструменты экосистемы) и оцени, достижим ли уязвимый код из проекта;
- устаревшие пакеты, особенно с отставанием на мажорную версию или вышедшие из поддержки, включая версию рантайма;
- заброшенные библиотеки: давно нет релизов, нет реакции на issues, один мейнтейнер;
- неиспользуемые и дублирующие друг друга зависимости (две библиотеки для одной задачи);
- тяжёлые зависимости ради одной небольшой функции;
- отсутствие или рассинхрон lock-файла, незафиксированные версии, установку из непроверенных источников;
- несовместимые с проектом лицензии;
- зависимости, которые попадают в продакшн, хотя нужны только для разработки.

Для каждой находки: риск, рекомендуемое обновление или замена, ожидаемые breaking changes по changelog и риск регресса.

Сгруппируй обновления в независимые пакеты, которые можно применять и проверять по отдельности, — от самых безопасных к самым рискованным.
