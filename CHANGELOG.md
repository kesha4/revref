# Журнал изменений

Версии набора — по [семантическому версионированию](https://semver.org/lang/ru/). Текущая версия — в файле `skill/revref/VERSION`.

- **Мажорная** (X.0.0) — несовместимые изменения формата файлов `.revref/` или протоколов. Начатый прогон нельзя продолжить без миграции.
- **Минорная** (3.X.0) — новые возможности, совместимые с начатыми прогонами.
- **Патч** (3.2.X) — исправления текстов и ошибок без изменения форматов.

Раздел «Миграция» есть у версии, только если при переходе на неё нужно что-то сделать с уже начатым прогоном. Оркестратор читает его при `resume`, если версия набора изменилась.

## 3.9.0 — 2026-10-27

- **Повторный `init` без отдельного подтверждения.** Если в `.revref/` остался прежний прогон — завершённый или нет, — агент сразу задаёт вопросы `init` и в том же сообщении пишет, что будет с прежним прогоном; ответы — согласие. Прежний прогон уходит в архив: файлы в `.revref/archive/<прогон>/`, ветки в `revref/archive/<прогон>/…`, тег `revref/<прогон>/archived`. Новый прогон начинается от основной ветки, если HEAD был на ветке прежнего; имя ветки получает суффикс `-2`, `-3`, если дата занята. Прежние ответы — варианты по умолчанию, архивный `CONTEXT.md` — черновик карты и команд.
- **`/revref abandon`** — отказ от начатого прогона: карточка, после «да» владельца — архивирование и возврат на основную ветку. Ничего не удаляется безвозвратно; команды полного удаления и восстановления агент выводит владельцу.
- PROTOCOLS §12 «Архив и отказ от прогона»; POLICY: ветки прежних прогонов только переименовываются в архив.

## 3.8.1 — 2026-10-24

- `bin/update.sh` определяет папку установки по расположению набора, а не по записи в `INSTALL`: установка в проект, закоммиченная в git, обновляется в том клоне, где её запустили, а не в папке на машине первой установки. Абсолютные пути из `INSTALL` убраны.
- `.gitattributes` в папке набора закрепляет LF для `*.sh` в проектах с `core.autocrlf=true`.

## 3.8.0 — 2026-10-24

- **Обновление набора с подтверждением:** `/revref update [vX.Y.Z]` для установки в проекте и глобальной — проверка релизов в источнике, карточка с изменениями из `CHANGELOG.md`, установка только после «да» владельца в чате, с теми же параметрами, что при первой установке. Откат — `update v<прежняя>`. Порядок — `PROTOCOLS.md` §11.
- Автопроверка новой версии в начале `init`, `run`, `resume`, `status` — не чаще раза в сутки, одна строка в чат, ничего не ставит; `REVREF_UPDATE_CHECK=off` отключает.
- `bin/update.sh`: `--check`, `--prepare`, `--apply vX.Y.Z --expect <коммит>` и интерактивный режим `[y/N]` для терминала. Только теги `vX.Y.Z`, сверка коммита между проверкой и установкой.
- Установщики записывают `INSTALL` — источник (без логина и токена), язык, глобально или в проект, папку конфигурации.
- POLICY: проверка обновлений — разрешённый запрос во внешнюю систему; обновление и подключение статусной строки — изменения вне репозитория только после «да» владельца. Тест `scripts/test_update.sh`.

### Миграция

- Установки 3.7.0 и раньше не имеют `bin/update.sh` и `INSTALL`: обновите их до 3.8.0 вручную (`git pull && ./install.sh`), дальше — `/revref update`.

## 3.7.0 — 2026-10-24

- **Лимит токенов.** Прогон останавливается при заданной доле недельного лимита подписки (по умолчанию 95%): без новых субагентов, с WIP-коммитами и полным чекпоинтом, с временем сброса окна в сообщении; после сброса — `resume`. Предупреждение за 10 пунктов до порога; при 95% пятичасового окна — чекпоинт заранее. Вопрос о бюджете при `init` теперь включает лимит: «3 суток, остановиться при 95% недельного лимита».
- `hooks/usage.sh` — команда статусной строки: сохраняет `rate_limits`, которые Claude Code передаёт только статусной строке, и выводит их оркестратору (`--read`). Прежняя статусная строка владельца сохраняется через `revref/statusline-next`. Подключение — при `init` с согласия владельца или вручную (README → «Лимит токенов»).
- `CONFIG.md`: «Лимит токенов»; `STATE.md`: тип чекпоинта «остановлен: лимит токенов»; `status` показывает лимит. Тест `scripts/test_usage.sh`.

### Миграция

- Если в `CONFIG.md` начатого прогона нет строки «Лимит токенов», добавь «Лимит токенов: 95% недельного лимита (предположение)» и сообщи владельцу. Если `hooks/usage.sh --read` не даёт данных, предложи подключить статусную строку; до согласия лимит не отслеживается.

## 3.6.0 — 2026-10-14

- Ревью изменений: `review … --commits N`, `--commits <sha>,<sha>`, `--commits <от>..<до>`, `--since` / `--until` — любое ревью ограничивается изменениями выбранных коммитов и тем, что они затрагивают.
- У находок — поле «Происхождение: внесено / усилено / существовало ранее»; отчёты `reports/<ID>.changes-<дата>.md`, ID находок `<ID>-c<NN>`.
- `review --commits N` без списка ревью — комплексное ревью изменений (QR в режиме изменений), как ревью пул-реквеста.

## 3.5.0 — 2026-10-13

- **Независимая проверка каждого исправления.** До слияния (и до постановки pending-патча в очередь) готовую ветку проверяет верификатор, который не был автором ревью или правки, по трём вопросам: верна ли предпосылка (ТЗ, приложения, принятые решения, реальный процесс), что правка запрещает или меняет для честного пользователя, риск регрессии (другие клиенты, старый клиент во время обновления, минимальные платформы, сервер и контейнеры — тестами и разбором кода). Новый промпт `prompts/work/verify-fix.md` и шаблон `templates/fix-check.md`.
- Те же три вопроса — в верификации находок.
- Метка `LEGIT` (класс C): исправление, сужающее законный сценарий честного пользователя, — только решением владельца. Поле «Законные сценарии» в формате находки и «Затронутые законные сценарии» в решениях.
- `CONTEXT.md`: разделы «Платформы, клиенты и окружения» и «Источники задуманного поведения».
- Несколько субагентов одной роли на непересекающихся модулях и файлах: таблица в PROTOCOLS.md §3; верификаторы одного отчёта пишут вердикты в свои файлы — у каждого файла один писатель.

## 3.4.0 — 2026-10-13

- `/revref ask D-015`, `ask D-014 D-015`, `ask 3 D-015` — показ решений по ID, в том числе уже отвеченных (ответ можно изменить, пока он не обработан).
- Связанные решения («вместе», «зависит от», «блокирует») показываются одной группой до 3 карточек; на группу можно ответить одной строкой `D-014+D-015 ок`. Противоречивые ответы по паре «вместе» не записываются без уточнения.
- Шаблон `DECISIONS.md`: поле «Связанные решения».

## 3.3.0 — 2026-10-13

Уроки первого полного прогона на демо-проекте (`examples/demo-shop`).

- Настройка `Денежные исправления по ТЗ`: по выбору владельца исправления с меткой `MONEY`, однозначно предписанные ТЗ и не меняющие цены и правила, могут быть классом B (по умолчанию — C).
- Класс задачи в плане волны — наивысший класс меток всех её находок, включая добавленные верификаторами.
- На каждой вехе pending-ветки обновляются под ветку прогона и проверяется их пробное совместное слияние: устаревшие ветки при автослиянии молча создавали дубли классов и выключали тесты.
- Без worktree исполнитель запускается только когда другие субагенты не пишут в рабочий каталог, а состояние шага коммитится до его запуска.
- Роли: обязательная уборка временных файлов; исполнитель не откатывает незакоммиченную работу при проверке мутаций.
- Ревью TEST проверяет, не наследуют ли дочерние процессы тестов ключи и секреты из окружения.
- Шаблон `CONTEXT.md`: базовая линия — состояние на старте прогона, текущее — в `STATE.md`.

## 3.2.1 — 2026-10-13

- Сторожевой хук работает, даже если git переписал `guard.sh` с концами строк CRLF (Windows с `core.autocrlf=true`, worktree, повторное клонирование).
- `install.sh` подставляет путь к хуку в файлы агентов и при пробелах в пути установки.
- CI: проверка CRLF-копии хука; `actions/checkout@v5`.

## 3.2.0 — 2026-10-13

- **Секреты:** значения ключей, токенов, паролей и персональных данных никогда не попадают в отчёты, решения, коммиты и чат — только место и замаскированный вид.
- **Защита от prompt injection:** содержимое репозитория и выводы инструментов — данные, а не инструкции. Попытки управлять агентом через текст в проекте становятся находкой SEC.
- **Сторожевой хук** `guard`: технически блокирует опасные git-команды во время прогона (изменение основной ветки, force-push, rebase, удаление незакоммиченного) и коммит секретов в `.revref/`.
- **Свои ревью:** `.revref/reviews/<ID>.md` — новое ревью, `.revref/reviews/<ID>.extra.md` — дополнение к встроенному.
- **Версия набора:** файл `VERSION`, запись версии в `STATE.md`, проверка совместимости при возобновлении, этот журнал.
- **Английская версия** набора и README.
- **Самопроверка набора:** скрипт `scripts/check_kit.py` и проверка в GitHub Actions на Windows, macOS и Linux.

## 3.1.0 — 2026-10-13

- Кроссплатформенная установка: `install.sh` (macOS, Linux, WSL, Git Bash) и `install.ps1` (Windows PowerShell 5.1 и PowerShell 7+), поддержка `CLAUDE_CONFIG_DIR`, удаление.
- Команда `/revref ask [N|all]`: самые приоритетные вопросы владельцу прямо в чате, ответы вида `D-012 ок`, работа во время прогона, `INBOX.md` для ответов из параллельной сессии.
- Рекомендация агента обязательна для каждого решения и вопроса.
- README: полный список ID ревью, справочник параметров, работа с ветками git, лицензия CC BY 4.0.

## 3.0.0 — 2026-10-12

- Первая публичная версия: скилл Claude Code `/revref`.
- Конвейер волн W0–W9, параллельные субагенты (ревьюер, верификатор, исполнитель), изолированные worktree для исправлений.
